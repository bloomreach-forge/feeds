# Atom Feed Enrichment Guide

## Overview

Atom feeds generated by the Bloomreach feeds plugin automatically include document properties as custom namespace fields, enriching the feed with additional information beyond the standard Atom specification.

This feature leverages Atom's extension element capability (RFC 4287) to include rich document metadata without violating the Atom spec.

## Why Enrichment?

The Atom 1.0 specification defines a strict set of core elements: title, author, updated, entry ID, links, content, and summary. While these cover basic feed requirements, documents often contain additional useful information:

- **introduction** - Brief summary/description
- **content** - Full article body
- **location** - Geographic location/origin
- **author** - Custom author metadata
- **language** - Document language code
- **copyright** - Copyright/licensing info
- **source** - Original source

### Atom Compliance

Per RFC 4287 Section 6 ("Extensibility"):
> "Atom consumers MAY ignore any foreign markup in the document they don't understand."

By using custom namespace elements, enrichment data is preserved for clients that can understand it, while remaining transparent to standard Atom readers. This maintains full spec compliance.

## How It Works

### Default Enrichment Fields

The `Atom10EnrichedModifier` automatically includes these fields if they exist on your document:

```
introduction    → <br-feed:introduction>...</br-feed:introduction>
content         → <br-feed:content>...</br-feed:content>
author          → <br-feed:author>...</br-feed:author>
location        → <br-feed:location>...</br-feed:location>
source          → <br-feed:source>...</br-feed:source>
language        → <br-feed:language>...</br-feed:language>
copyright       → <br-feed:copyright>...</br-feed:copyright>
```

### Custom Namespace

Fields are added under the `br-feed` namespace:
```xml
xmlns:br-feed="http://bloomreach-forge.example.org/feed"
```

### Example Atom Entry with Enrichment

```xml
<?xml version="1.0" encoding="UTF-8"?>
<feed xmlns="http://www.w3.org/2005/Atom"
      xmlns:br-feed="http://bloomreach-forge.example.org/feed">
  <title>News Feed</title>
  <entry>
    <!-- Standard Atom fields -->
    <title>Breaking News</title>
    <author><name>John Doe</name></author>
    <updated>2024-01-27T10:00:00Z</updated>
    <id>urn:uuid:60a76c80-d399-11d9-b91C-0003939e0af6</id>
    <content>Full article text goes here...</content>

    <!-- Custom enrichment fields (extension elements) -->
    <br-feed:introduction>Brief summary of the news</br-feed:introduction>
    <br-feed:location>Amsterdam, Netherlands</br-feed:location>
    <br-feed:source>Internal News Portal</br-feed:source>
    <br-feed:language>en</br-feed:language>
    <br-feed:copyright>© 2024 Example Corp</br-feed:copyright>
  </entry>
</feed>
```

## Configuration

### Default Configuration

No configuration needed! The enriched modifier is enabled by default for Atom feeds with the standard enrichment fields listed above.

### Custom Enrichment Fields

To customize which fields are included, override the Atom modifier in your demo or application Spring configuration:

**File**: `hst-cms-rest.xml` (or your custom Spring config)

```xml
<bean id="atomModifier" class="org.bloomreach.forge.feed.api.modifier.Atom10EnrichedModifier" scope="singleton">
  <property name="enrichmentFields">
    <list>
      <value>introduction</value>
      <value>content</value>
      <value>location</value>
      <value>customField1</value>
      <value>customField2</value>
    </list>
  </property>
</bean>
```

### Combining with Property Filtering

The enriched modifier extends the property filtering modifier, so you can combine both features:

```xml
<bean id="atomModifier" class="org.bloomreach.forge.feed.api.modifier.Atom10EnrichedModifier" scope="singleton">
  <property name="enrichmentFields">
    <list>
      <value>introduction</value>
      <value>content</value>
      <value>location</value>
    </list>
  </property>
</bean>

<!-- Configure filter on feed descriptor: -->
<!-- Filter by Property: status -->
<!-- Filter by Value: published -->
```

This will:
1. Only include entries where `status == "published"` (filtering)
2. Add introduction, content, and location as custom namespace fields (enrichment)

## Field Resolution

The enrichment mechanism uses Java reflection to find getter methods on document beans:

**Field name** → **Getter method** → **XML element**
```
introduction  → getIntroduction()  → <br-feed:introduction>...</br-feed:introduction>
customField1  → getCustomField1()  → <br-feed:customField1>...</br-feed:customField1>
```

### Requirements

For a field to be included:
1. The bean must have a public getter method (e.g., `getIntroduction()`)
2. The method must return a non-null value
3. The value's `.toString()` must produce a non-empty string
4. The field must be listed in the `enrichmentFields` configuration

### Missing Fields

If a field is configured but not found on a document:
- **Silently skipped** - No error is thrown
- **Logged at DEBUG level** - Check logs if you expect the field to appear
- **Affects feed generation minimally** - Other fields continue to enrich normally

## Best Practices

### 1. Be Selective with Fields

Only include fields that are meaningful for feed consumers. Too many fields clutter the feed.

```xml
<!-- Good: focused set of enrichment fields -->
<list>
  <value>introduction</value>
  <value>location</value>
</list>

<!-- Avoid: too many fields -->
<list>
  <value>introduction</value>
  <value>location</value>
  <value>internalId</value>
  <value>workflowStatus</value>
  <value>approvalDate</value>
  <!-- ... 20+ more fields ... -->
</list>
```

### 2. Use Meaningful Field Names

Choose field names that clearly communicate their purpose to feed consumers.

```
✓ introduction    (clear: brief summary)
✓ fullContent    (clear: complete text)
✗ intro          (ambiguous)
✗ data1          (meaningless)
```

### 3. Handle HTML Content

If content fields contain HTML, ensure proper handling:

```java
// Document field that contains HTML
public String getHtmlContent() {
    return "<p>Article text with <strong>formatting</strong></p>";
}
```

The HTML will be XML-escaped in the Atom feed. Feed readers can decode it if they choose.

### 4. Test with Feed Readers

Test your enriched Atom feeds with various feed readers:
- **Standard readers** should ignore unknown namespaces and still display the feed
- **Smart readers** may recognize and display custom fields
- **API consumers** can parse custom namespace fields as needed

## Extending Enrichment

### Create Custom Enrichment Logic

Extend `Atom10EnrichedModifier` for specialized enrichment:

```java
public class MyCustomAtomModifier extends Atom10EnrichedModifier {

    @Override
    public void modifyEntry(HstRequestContext context, Entry entry, HippoBean bean) {
        // First apply standard enrichment and filtering
        super.modifyEntry(context, entry, bean);

        // Then add custom logic
        if (bean instanceof MyCustomDocument) {
            MyCustomDocument doc = (MyCustomDocument) bean;
            addCustomFields(entry, doc);
        }
    }

    private void addCustomFields(Entry entry, MyCustomDocument doc) {
        // Add specialized fields
        // ...
    }
}
```

### Programmatic Field Management

You can also modify enrichment fields programmatically:

```java
Atom10EnrichedModifier modifier = new Atom10EnrichedModifier();

// Add field
modifier.addEnrichmentField("customField");

// Remove field
modifier.removeEnrichmentField("copyright");

// Reset to defaults
modifier.resetToDefaults();

// Get current configuration
List<String> fields = modifier.getEnrichmentFields();
```

## Troubleshooting

### Custom Fields Not Appearing

**Symptom**: Configured fields don't show up in Atom feed

**Diagnosis**:
1. Check that bean has a public getter method
2. Method name must follow pattern: `get<FieldName>()`
   - Field `introduction` → method `getIntroduction()`
3. Check logs for DEBUG messages about field resolution
4. Verify field value is not null/empty

**Solution**:
```bash
# Enable debug logging to see enrichment details
log4j.logger.org.bloomreach.forge.feed.api.modifier.Atom10EnrichedModifier=DEBUG
```

### Namespace Not Displaying

**Symptom**: Custom fields appear but namespace prefix is wrong or missing

**Cause**: Feed reader/parser handling of namespaces

**Solution**: Different feed readers handle namespaces differently. Standard Atom readers will ignore the namespace; specialized readers will properly recognize it.

### Performance Impact

**Question**: Does enrichment slow down feed generation?

**Answer**: Minimal impact. Enrichment uses reflection to look up methods, which happens once per entry and is cached by the JVM. For typical feed sizes (10-100 entries), enrichment adds <50ms overhead.
